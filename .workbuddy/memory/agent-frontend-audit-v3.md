# Bambook Agent 前端审计报告 v3

> 2026.06.14 · Bamboo

---

## 之前我错在哪

上一版审计报告把你们的系统说得太好了。"透明度高"、"过程拆解出色"——这些都对，但不影响一个事实：**当前的交互体验对企业用户来说是不可用的。**

证据就是你刚才发我的截图。我原以为截图上会是一个"还算工整但缺个图表面板"的界面，实际上看到的是一个信息层级混乱、英文技术术语满天飞、用户看完不知道接下来该干什么的工程草稿。

所以这版审计推翻重来。只说真话。

---

## 截图里暴露的四个核心问题

### 问题 1：英文 Dev 术语直接暴露给中文企业用户

`TaskGraphPanel` 里渲染的四个节点，标题是：

> 数字档案查询 → 订单档案查询 → assess → respond

"数字档案查询"和"订单档案查询"是 `describeAgentTool()` 从 `toolId` 推导出来的中文标签——这部分没问题。但 "assess" 和 "respond" 是什么呢？它们是后端 `metadata.steps[].kind` 的原始值，前端没有做任何翻译或包装，直接原样丢给用户。

再看 `AgentTimeline` 里的卡片标签：

- `Task Graph` — 不知道是什么
- `Thought` — 英文
- `Plan` — 英文
- `Final Answer` — 英文
- `TEXT` — 这个最离谱，完全不知所云

这些全部是 `TaskGraphPanel`、`ThoughtCard`、`PlanCard`、`FinalAnswerCard` 组件里写死的英文标签。对于一个中文企业系统，这种双语混排已经不是"国际化不到位"的问题了——它让界面看起来像是一个还在调试阶段的工程 prototype。

**代码位置**：`AgentTimeline.tsx` 第 182 行的 `Thought`、第 208 行的 `Plan`、第 370 行的 `Final Answer`、第 407 行的 `Task Graph`。

### 问题 2：所有信息的视觉权重一样

截图里，Task Graph 大卡片占据了消息顶部大约 1/3 的空间，下面是"Agent 推理迭代"的步骤列表，再下面是一段 Markdown 文字。

视觉上，这三块内容的字号、间距、边框都差不多。用户的眼睛不知道该看哪里。

更糟糕的是，最重要的一句话——Agent 的结论——淹没在这一大堆里。**"我查了本轮 Bambook 数据中心订单结果：没有命中 Peerless 本季订单"** 这句话才是用户真正关心的，但它和"Agent 推理迭代 · 3 步 · 3 次调用"这样的元信息挤在一起，没有任何强调。

### 问题 3：失败/空结果和成功结果长得一模一样

Agent 查了一个客户，数据库里没有订单。这是非常正常的情况。但当前的界面没有任何视觉线索告诉用户"这是个空结果"。

没有状态图标（❌ 空 / ✅ 有数据 / ⚠️ 部分成功）。  
没有区分颜色（空结果不应该和成功结果用同一个色调）。  
没有解释原因（"customer 为空"、"dueDateFrom 为空"这些内部参数直接暴露给用户）。

### 问题 4：用户不知道该做什么

Agent 说"查完了，没有数据"。然后呢？  界面到此为止。

没有"换个客户搜索"的快捷入口。  
没有"查看所有订单"的引导按钮。  
没有"告诉我更多关于 Peerless 的信息"的追问提示。

用户只能自己重新组织语言，再发一条消息。这种"对话死胡同"的体验，是 AI 产品最大的流失点。

## 根本原因：组件体系是为"Agent 开发者"设计的，不是为"企业用户"

看完代码后，我能理解为什么会导致这种情况。整个组件的设计思路是：

> "把 Agent 做了什么完整地展示出来。"

这个意图本身没问题，但问题出在**没有做信息分级**。现在所有东西都用一个优先级来展示——Task Graph、推理步骤、工具参数、最终回复——全部平铺。

对于调试 Agent 行为的人来说，这是宝藏。对于只想查一个订单的人来说，这是噪音。

---

## 重新排序的优先级

之前审计里 P0 是 Artifacts 双栏布局。看完截图后，我把优先级重排了。

### 🔴 P0-紧急：消息口径与视觉层级

**对应代码**：`AgentMessageCard.tsx` 的消息正文渲染区域（第 162-171 行）、`AgentTimeline.tsx` 的所有卡片标签。

**要做什么**：

1. 把所有英文标签改成中文。`Thought` → `思考`，`Plan` → `执行计划`，`Final Answer` → `本轮结论`，`Task Graph` → `任务流程`。这是最小改动，但效果立竿见影——界面从"调试模式"变成"产品模式"。

2. 消息卡片引入**结论先行**的视觉层级。最上面是 Agent 的核心结论（大字号 + 状态图标），中间是可折叠的过程细节，最下面是行动引导按钮。`AgentMessageCard.tsx` 目前把 Markdown 正文和 Timeline 平级渲染，需要改成主次关系。

3. 区分结果状态。失败/空结果/成功/部分成功用不同的颜色和图标区分。这不是为了美观——是让用户不用读文字就知道结果好坏。可以在 `AgentMessageCard` 或 `AgentTimeline` 层面，根据事件流的最终状态决定卡片的色调。

4. 技术诊断信息默认折叠。现在 `AgentTimeline` 的 `ToolCallCard` 已经支持折叠了（第 242 行 `isExpanded`），但**消息正文里的技术参数（"customer 为空"、"total = 0"）没有折叠机制**。这些不应该出现在 MarkdownRenderer 渲染的主回复中——它们是调试信息，应该放在折叠面板里。

### 🟡 P1：时间轴的视觉瘦身

**对应代码**：`AgentTimeline.tsx` 的 `TaskGraphPanel`（第 397 行）和 `IterationGroup`（第 124 行）。

**要做什么**：

1. `TaskGraphPanel` 默认折叠为一行摘要，点击才展开。现在它一出现就铺满半个屏幕。
2. `IterationGroup` 已完成步骤的卡片默认收拢为一个横条，只显示"第 N 步 ✓ 数字档案查询"，让用户能扫一眼知道做了什么，但不占空间。
3. 运行中的步骤（蓝色转圈）保持展开，因为用户需要看到 Agent 正在干什么。

### 🟢 P2：工件展示（原 P0）

之前审计里提的 Artifacts 双栏布局降到 P2。这不代表它不重要，而是——**如果基础的消息卡片都让用户不知道看哪里，一个花哨的右侧面板只会让问题更严重。**

等 P0 和 P1 做好，信息层级清楚了，再来激活 `ChatMessage.artifacts` 字段做双栏布局，才是正当时机。

## 改造后的交互对比（和截图相同场景）

### 现在的体验

Agent 查 Peerless 订单，没查到。用户看到的是：

- 一个占据 1/3 屏幕的大白卡，写着 `TASK GRAPH`，里面有 4 个节点
- 下面一排小卡片：`Thought` → `Plan` → 工具调用
- 再下面一个绿色框写着 `Final Answer`，里面说"评估完成，空结果"
- 再下面是灰色框 `TEXT`，里面说"因此目前不能生成趋势图"
- 最下面一段 Markdown 正文，混杂着 `total = 0` 之类的技术字段

**用户读完需要 30 秒。读完还是不知道接下来该干什么。**

### 改造后的体验

Agent 查 Peerless 订单，没查到。用户看到的是：

一条消息卡片，顶部有一个浅灰色的圆角条，上面写着 `⭐ Peerless — 查询完成`。旁边一个灰色圆圈图标。

卡片的正文区直接说：

> **没有找到 Peerless 本季的订单数据。**  
> 可能是因为：该客户本季尚未下单，或客户编码需要确认。

下面两个小按钮，颜色是 `--os-vnext-brand-blue`：

```
[查看 Peerless 全部订单]    [搜索其他客户]
```

下面有一条浅色虚线分割线。分割线下面是折叠的：

```
▸ 查看执行细节（3 步 · 3 次调用）
```

用户点开，才会看到数字档案查询 → 订单档案查询 → 分析的步骤列表。每步一行，不占空间。

**用户读完需要 5 秒。并且知道接下来可以做什么。**

## 这不是推倒重来

你可能会担心：上面说的这些是不是要重写 `AgentTimeline` 和 `AgentMessageCard`？

不是。

代码基础是好的。`finalizeAgentEvents` 的事件收敛逻辑不用改。`buildAgentTimeline` 的聚合逻辑不用改。`ToolCallCard` 的折叠 JSON 不用改。`MarkdownRenderer` 不用改。

要改的基本只有三件事：

1. **标签文本**：`AgentTimeline.tsx` 里 4 个英文标签改成中文。这在代码里就是改字符串，5 分钟的事。
2. **MessageCard 的渲染顺序**：`AgentMessageCard.tsx` 目前是 Title → Timeline → Text → Sources。改成 Title → Summary（新，结论先行）→ Text → Actions（新，行动引导）→ Detail（折叠，包含 Timeline + Sources）。这涉及到在 `AgentMessageCard` 中新增一个"结论提取"逻辑和两个可选渲染块。
3. **TaskGraph 默认折叠**：`AgentTimeline.tsx` 中给 `TaskGraphPanel` 加一个 `isExpanded` 状态，默认 false。这也只是一个 useState。

核心组件树的改动量很小——属于优化，不属于重构。

## 关于设计语言

之前讨论的 BAMBOOK_OS / OS_MATERIAL / osVNext 约束全部保留。所有新加的 UI 元素：

- 结论区域的色调用 `BAMBOOK_OS.tone.text.*` 体系
- 行动按钮用 `BAMBOOK_OS.controls.actionControl.*` 
- 折叠面板用 `OS_MATERIAL.insetSurface`
- 状态图标颜色用 `--os-vnext-brand-blue` 品牌色
- 过渡动画用 `BAMBOOK_OS.motion.layoutTransition`

不走 compiler 禁止的逃逸路径。

## 什么时候做 P2 的 Artifacts

等 P0 的中文化和信息层级改完之后，用户看到"任务查询成功，找到 47 条订单"时，消息底部会自然出现工件缩略卡片。那时候再做右侧面板就顺理成章了——因为用户已经有清晰的信息优先级认知，"点卡片 → 看面板"是直觉操作，而不是困惑下的试探性点击。
