### [新知] 业务流程硬门禁
两份规定揭示了多个不可跳过的审批门：裁剪前四项检查全通过、产前样双签、验货合格率/不合格率阈值校验。这些应直接编码为状态机转换条件，不是可选检查项。

### [新知] 角色缺失
当前 Bambook 8 个角色中无 production_manager（生产部）和 factory（工厂），但业务规定中生产部是独立审批节点（5A样衣评审、生产计划确认、验货报告出具），不能和 merchandiser 合并。

## ERP 改造升级规划

### 背景
Kevin 要求基于业务规定分析，规划 Bambook ERP 的改造升级。

### 完成的工作
- 通过 Explore agent 完整摸底现有 Prisma schema（40+ model）、60+ MCP 工具清单、订单状态枚举（6 个主状态）、角色定义（9 个角色）、已有生产/开发/发货流程代码
- 产出 `docs/erp-upgrade-plan.md`，5 个 Phase 分阶段改造方案：
  - ERP-1：生产管线数据层（3 个新 model: ProductionStage/PreCutChecklist/InspectionReport + 角色扩展 + Order 字段）
  - ERP-2：状态机 + 门禁引擎（10 阶段子状态 + 门禁规则 + 自动预警）
  - ERP-3：MCP 工具组（7 个 domain='production' 工具）
  - ERP-4：样衣管理增强（5A/普通分档 + 审批流分支）
  - ERP-5：前端看板 + Agent 监控

### 关键设计决策
1. 不改现有 6 个主状态枚举，生产阶段是子状态层
2. 门禁编码在状态机转换条件中，不是可选检查项
3. 复用已有审批体系（ApprovalRequest + AuditLog），不新建
4. 新模块走 MCP 工具组暴露给 Agent
5. ERP 改造与 Agent 架构升级可并行，数据层完全不依赖 Agent 改造

### [新知] 主状态 vs 子状态分层设计
现有 VALID_ORDER_STATUSES 只有 6 个（Pending/Confirmed/Production/Shipping/Delivered/Alert），但业务规定有 10 个阶段。解决方案是主状态保留不动，新增 ProductionStage 表跟踪子阶段，子阶段完成自动推进主状态。
