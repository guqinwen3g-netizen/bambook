## 0. 一句话目标

**本周（2026-08-21 当周）必须交付 `Bambook Enterprise OS v0.8`**：实现全部基础业务功能的完整、全面交付，让甲方（接收公司）能立刻投入真实业务使用。

## 2. 系统必要基础架构（随 v0.8 一并交付）

- 登录 / 权限 / 角色（RBAC）
- 数据导入导出（含历史数据迁移入口）
- 操作留痕 / 审计（**人工操作也要记录**）
- 基础 UI 骨架与导航（**遵循 BDS 规范搭建**，不额外花时间做设计打磨）

## 3. AI Agent 原生接入 = 纯占位（不在 v0.8 交付）

- 所有 "AI Agent 原生接入" 相关内容（智能体对话、自动规划、MCP 工具智能调用、Agent 中栏渲染等）**v0.8 阶段仅做占位 / 入口保留**，不做真实能力。
- 实际交付推迟到 **2026 年 9 月下一阶段目标**。
- 理由：第一轮优先让业务员**人工**驱动业务跑通；Agent 自动化是第二波。

## 4. 质量红线（降级边界，务必遵守）

| 维度                                  | v0.8 要求                                              |
| :---------------------------------- | :--------------------------------------------------- |
| **UI / 视觉（配色 / 间距 / 圆角 / 组件 / 层级）** | **按现有 BDS（Bambook Design System）**；但不额外花时间做设计打磨 / 精修 |
| 功能完整性（21 板块能录入 / 查询 / 跑通）           | **不可降级**，必须全面可用                                      |
| 数据正确性（金额 / 汇率 / 单位换算 米·码·公斤）        | **不可降级**，算错是财务事故                                     |
| 数据不丢 / 不串                           | **不可降级**                                             |
| 操作留痕                                | **不可降级**（人工操作也要记录）                                   |

> **BDS（Bambook Design System）定义**：项目唯一 UI 真源 = `styles/bds/tokens.css` + `components.css` + `layout.css`（由 `index.css` 引入）；token 与组件刻度见 `tailwind.config.js` 的 `bds-*` 系列；权威设计宪法见 `docs/design-system/`（含 `design-constitution.md`、`governance.md`、`page-consistency-ledger.md`）。  
> **铁律**：任何新页面 / 新组件必须复用 BDS 原语（`.bds-*` 类库 + token），**禁止另起视觉体系、禁止临时手写裸 CSS 兜底**。v0.8 不追求"更美"，但绝不允许"不按 BDS"。

## 5. 执行纪律（给 coding agent 的硬指令）

1. **本轮 KPI = "人工能跑通"（L1/L2），不是"生产打磨"（L3）。** 不要把时间花在 UI 设计打磨上；但所有界面**必须**走现有 BDS（见 §4 真源），禁止临时手写裸样式、禁止偏离 BDS。
2. 21 板块全覆盖优先于单板块深度；不要挑喜欢的做、不要加需求池外的事。
3. **严禁**在本轮碰 AI Agent 原生能力的实质实现；只留占位。
4. 任何代码只跑在 **Dev 环境**（localhost:3000 / Electron / Local Panda Hub）。生产推送流程见 `docs/ARCHITECTURE.md` §6 与 `docs/DEPLOY_SOP.md`。

## 6. 环境提醒

开发与生产端点、数据库完全隔离，切勿混淆。详见 [`docs/ARCHITECTURE.md` §6 运行环境拓扑](./ARCHITECTURE.md)。
