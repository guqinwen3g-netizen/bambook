## §2 业务定位与目标

### 2.1 业务定位

`Products` 是 Bambook 服装生产管理系统的「数字资产中枢」——承载面料、成衣、辅料三类核心生产资料的完整数字档案。所有采购、库存、订单、报价、BOM、生产工单均以 `ProductAsset` 为外键锚点，构成「以物为中心」的跨模块协同网。

### 2.2 三档定位

| 档案 | 主类目 | Profile 模型 | 业务用途 |
| --- | --- | --- | --- |
| 面料档案 | `Fabric` | `FabricProfile` | 纺织底料的技术规格库（克重/门幅/成分/认证/价格历史），是采购与开发的物料主数据。 |
| 成衣档案 | `Garment` | `GarmentProfile` | 款式 BOM 载体（款号/尺码/工序/材料清单），是订单与生产的款式主数据。 |
| 辅料档案 | `Trimmings` | `TrimmingProfile` | 纽扣/拉链/衬布等辅料的规格库，是 BOM 的辅料消耗单元。 |

> `Accessories / Merchandise / Other` 三个主类目虽存在枚举，但暂未启用专属 Profile，沿用 `ProductAsset` 基础字段承载。

### 2.3 核心目标

1. **一物一档**：每个 `ProductAsset` 唯一 `sku` 全局唯一（`@unique`），二维码可生成（ProductsManager.tsx 第 3 行 `qrcode`）。
2. **三档解耦**：面料/成衣/辅料各自独立 Profile，避免字段冗余与误用。
3. **多维度分类**：除主类目外，可挂 `ProductClassificationLink`，支持 `category / supplier / customer / certification / price / status` 六维视图。
4. **价格与认证全链路追溯**：`FabricPriceHistory` 按价格类型分轨，`FabricCertification` 含有效期。
5. **PDML 外部原料库接入**：`PdmlRawFabric` 作为外部 ERP 同步缓存，可一键映射为 `ProductAsset`。
6. **档案完整度可度量**：前端按 `images / basic / specs / pricing / risk / notes` 六段式分页表单（ProductsManager.tsx 130–136 行）组织字段，便于补全。

## §3 核心概念与术语

| 术语 | 定义 |
| --- | --- |
| `ProductAsset` | 产品档案聚合根，承载 SKU/名称/主类目/季节/成本/状态。 |
| `MainCategory` | 一级类目枚举（6 个），决定档案的 Profile 类型。 |
| `ProductSubCategory` | 二级类目（如「西装 / Suit」「纽扣 / Button」），由 `mainCategory` 索引。 |
| `FabricProfile` | 面料技术规格扩展（1:1 挂 ProductAsset，`@unique` 约束）。 |
| `GarmentProfile` | 成衣款式扩展（80+ 字段，覆盖款式/尺码/BOM/客户/工厂）。 |
| `TrimmingProfile` | 辅料规格扩展（30+ 字段，覆盖材质/规格/颜色/库存/合规）。 |
| `FabricCompositionLine` | 面料成分行（百分比累加，关联 `MaterialCompositionTerm` 术语库）。 |
| `FabricCustomerCode` | 客户专属编码（一物多客，每客户独立 client code）。 |
| `FabricPriceHistory` | 价格历史（按 `priceType = factory/customer/sample/cutting` 分轨）。 |
| `FabricCertification` | 面料认证（OEKO-TEX/GRS 等，含 `validUntil`）。 |
| `PdmlRawFabric` | PDML 外部 ERP 同步缓存（`gsid + sourceId` 唯一）。 |
| `Insight` | 洞察笔记（轻量 KV，`fact + importance + isPinned`）。 |
| `ProductImage` | 产品图片（含 `isPrimary` 主图标记与 `sortOrder`）。 |
| `ProductClassificationLink` | 多维分类链接（`productAssetId × classificationId` 唯一约束）。 |

## §4 数据模型概览

### 4.1 聚合根关系图

```
                 ┌──────────────────────┐
                 │   ProductAsset       │  聚合根
                 │  id, sku, name,      │
                 │  mainCategory,       │
                 │  subCategoryId,      │
                 │  season, cost, status│
                 └──────────┬───────────┘
                            │ 1:1 @unique
       ┌────────────────────┼────────────────────────┐
       │                    │                        │
┌──────▼─────────┐  ┌──────▼─────────┐    ┌─────────▼────────┐
│ FabricProfile   │  │ GarmentProfile  │    │ TrimmingProfile  │
│ (面料技术规格)  │  │ (成衣款式BOM)   │    │ (辅料规格)       │
└──────┬─────────┘  └─────────────────┘    └──────────────────┘
       │
       │ 1:N (反向聚合 productAssetId)
       ├─► FabricCompositionLine ──► MaterialCompositionTerm
       ├─► FabricCustomerCode
       ├─► FabricPriceHistory
       ├─► FabricCertification
       └─► ProductImage

ProductAsset ──► ProductClassificationLink ──► ProductClassification
ProductAsset ◄── PdmlRawFabric (映射后落地为 ProductAsset)
Insight (独立轻量模型)
```

### 4.2 关键约束

- `ProductAsset.sku` 全局 `@unique`。
- 三大 Profile 均以 `productAssetId` 为 `@unique` 外键（保证 1:1），`onDelete: Cascade`。
- 所有子集合（Composition/CustomerCode/PriceHistory/Certification/Image/ClassificationLink）外键均 `onDelete: Cascade`，随主档删除而级联软删。
- 所有时间字段为 `BigInt`（Unix ms），非 Prisma `DateTime`，便于跨时区一致与高精度排序。
- 软删除：所有模型含 `deletedAt BigInt?`，查询默认过滤。

### 4.3 ID 生成

- `ProductAsset.id`：前端可指定（`PROD-${now}` 兜底，见 productAssetMutationService.ts 54 行）。
- 其余子模型 ID 由服务端生成（`crypto.randomBytes` base64url）。

## §5 关键流程

### 5.1 档案创建流程

```
用户在 ProductsManager 表单填写
  ├─ basic 段：sku, name, mainCategory, subCategoryId, season, cost
  ├─ specs 段：根据 mainCategory 路由到 Fabric/Garment/Trimming 子表单
  ├─ pricing 段：FabricCustomerCode + FabricPriceHistory
  ├─ risk 段：FabricCertification
  ├─ images 段：ProductImage（ImageUploader）
  └─ notes 段：riskNote/specialNote/notes
       │
       ▼
apiService.createProductAsset(payload)
       │
       ▼
POST /api/products  →  productAssetMutationService.createProductAsset
       │
       ▼
$transaction {
  productAsset.create
  + Profile.create (按 mainCategory)
  + 子集合批量 create
  + writeRouteAuditLog
}
       │
       ▼
返回 ProductAssetDetail（含所有扩展）
       │
       ▼
前端 onUpdateProducts 回调合并到本地列表
```

### 5.2 PDML 原料同步与映射

```
PDML V_MLXX 视图 ──sync──► PdmlRawFabric（缓存）
                              │
                              │ 用户在「PDML 原料库」选中
                              ▼
                          映射为 ProductAsset (mainCategory=Fabric)
                              + FabricProfile (articleNo 等字段)
                              + FabricCompositionLine（如 rawData 含成分）
```

### 5.3 多维分类视图切换

```
用户切换 ClassificationView（category/supplier/customer/certification/price/status）
  │
  ▼
按维度对 ProductAsset[] 聚合（前端 useMemo 计算）
  │
  ▼
渲染分类卡片网格（PRODUCT_CARD_GRID_CLASS）
```

### 5.4 删除流程（软删除）

```
用户点击删除 → confirm 弹窗
  │
  ▼
DELETE /api/products/:id
  │
  ▼
$transaction {
  productAsset.update(deletedAt: now)
  + 子集合 update(deletedAt: now)（可选，查询已过滤）
  + writeRouteAuditLog
}
```

## §6 API 与服务契约

### 6.1 REST 端点（server/src/products/route.ts）

| Method | Path | 用途 |
| --- | --- | --- |
| GET | `/api/products` | 列表查询（支持 mainCategory / subCategoryId / season / status / search） |
| GET | `/api/products/:id` | 详情（含 Profile + 子集合） |
| POST | `/api/products` | 创建 |
| PUT | `/api/products/:id` | 更新 |
| DELETE | `/api/products/:id` | 软删除 |
| GET | `/api/products/:id/qr` | 生成二维码 PNG |
| POST | `/api/products/:id/images` | 上传图片 |
| GET | `/api/products/sub-categories` | 子类目列表 |
| POST | `/api/products/sub-categories` | 创建子类目 |
| PUT | `/api/products/sub-categories/:id` | 更新子类目 |
| DELETE | `/api/products/sub-categories/:id` | 删除子类目 |
| POST | `/api/products/pdml/sync` | 触发 PDML 同步任务 |
| GET | `/api/products/pdml/raw` | PDML 原料库分页查询 |
| POST | `/api/products/pdml/map` | PDML 原料映射为 ProductAsset |

### 6.2 服务层契约

- `productAssetMutationService.createProductAsset / updateProductAsset / deleteProductAsset`：事务化变更，支持可选 `tx` 参数（route 复用同事务，Agent flow 自开事务）。
- `productAssetWritable`：可写字段白名单，防止超范围更新。
- `lookbookService`：样品册（Lookbook）派生视图，按 season + mainCategory 聚合。
- `fabricRecommendationService`：面料推荐（基于成分/克重/认证相似度评分）。

### 6.3 业务事件

`productAssetMutationService` 内部 `writeRouteAuditLog` 写入 `AuditLog` 表，事件类型 `create_product_asset / update_product_asset / delete_product_asset`。

## §8 权限与审计

### 8.1 权限

- 创建/编辑/删除：需要登录态，actorId 写入 `AuditLog.actorId`。
- PDML 同步：需管理员权限（route 内校验）。
- 子类目 CRUD：任何登录用户可创建（默认内置 24 项，用户可扩展）。

### 8.2 审计

- 所有 mutation 通过 `writeRouteAuditLog` 同事务写入 `AuditLog`，含 `before / after` 快照。
- `source` 字段标记来源（`mutation-service:create_product_asset` 等）。
- `targetType = 'ProductAsset'`，`targetId = assetId`，便于按档案反查变更历史。

## §9 性能与扩展性

### 9.1 索引

- `ProductAsset`：`sku`（unique）、`season`、`mainCategory`（隐式）。
- `FabricProfile`：`millOrganizationId`、`millQuality`、`articleNo`。
- `GarmentProfile`：`styleNo`、`garmentCategory`、`customer`、`customerRelationId`、`factoryRelationId`、`factory`。
- `TrimmingProfile`：`trimmingCode`、`trimmingCategory`、`supplier`、`supplierRelationId`、`customer`。
- `PdmlRawFabric`：`gsid + sourceId`（unique）、`articleNo`、`factoryArticleNo`、`supplierName`、`productLine`、`registeredDate`、`sourceStatus`。
- 子集合均以 `productAssetId` 索引。

### 9.2 扩展性

- 三大 Profile 1:1 设计，可独立演进字段而不影响 ProductAsset 基础表。
- `ProductClassificationLink` 多维分类为 N:N，可任意扩展维度而不改表结构。
- `MaterialCompositionTerm` 术语库独立，成分行只引用 `termId`，新增术语不影响存量数据。
- `PdmlRawFabric` 独立缓存表，外部 ERP 字段变更不影响已映射的 ProductAsset。

### 9.3 已知性能优化点

- 列表查询默认不展开子集合，详情查询才 `include`（避免 N+1）。
- PDML 原料库分页 500/页（`PDML_RAW_PAGE_SIZE`）。
- 列表分类视图聚合前端 `useMemo`，避免服务端重算。

## §10 错误处理与边界

### 10.1 错误码

`ProductAssetMutationErrorCode`：

| Code | 触发条件 |
| --- | --- |
| `INVALID_INPUT` | sku/name/mainCategory 缺失 |
| `INVALID_AMOUNT` | cost 非合法 decimal |
| `NOT_FOUND` | 更新/删除时档案不存在或已软删 |
| `ALREADY_DELETED` | 重复删除 |
| `CREATE_FAILED` | DB 创建异常（如 sku 重复） |
| `UPDATE_FAILED` | DB 更新异常 |
| `DELETE_FAILED` | DB 软删异常 |

### 10.2 边界

- `cost` 用 `Decimal(18, 4)` 防浮点误差，服务端 `isValidDecimal` 校验。
- `sku` 重复时 DB 唯一约束抛错，service 转换为 `CREATE_FAILED`。
- 软删除后查询默认过滤，详情接口返回 `NOT_FOUND`。
- 子集合外键 `onDelete: Cascade`，主档软删后子集合查询自然过滤（业务层不显式级联软删）。

## §13 已知限制与技术债务

1. `Accessories / Merchandise / Other` 三个主类目未启用专属 Profile，沿用基础字段，扩展性受限。
2. `ProductAsset.status` 枚举混用中英文（`'Development' | 'Active' | 'Archived' | '开发样' | '产前样' | '大货样'`），需统一为英文 + i18n 映射。
3. `GarmentProfile` 字段过多（80+）且多为 `String?`，缺少结构化子表（如尺码表、工序、BOM 子行均为文本），后续可拆为独立模型。
4. PDML 同步任务无失败重试机制，需人工触发。
5. 图片上传未做 CDN 分发，当前依赖本地文件系统（`filePath`）。

## §14 演进路线

1. **GarmentProfile 结构化**：拆出 `GarmentSizeSpec / GarmentProcessStep / GarmentBOMLine` 子表，替代文本字段。
2. **Accessories/Merchandise Profile**：补充专属扩展模型。
3. **状态枚举国际化**：统一为英文枚举 + i18n key。
4. **PDML 同步增强**：定时任务 + 失败重试 + 增量同步。
5. **图片 CDN**：迁移至对象存储（S3/OSS），`filePath` 改为 URL。
6. **档案完整度评分**：基于六段表单填写率自动计算完整度百分比，提示补全。
7. **AI 智能补全**：基于历史档案 + PDML rawData 推荐字段值。
