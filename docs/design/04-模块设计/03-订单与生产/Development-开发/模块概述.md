## §2 模块定位与范围

### 2.1 在 ERP 全链路中的位置

```
客户询价 → 报价单(Quotation) → 【开发案例(DevelopmentCase)】 → 样衣验证(SampleNode) → 量产订单(Order) → BOM/采购/生产/出运/财务
                                    ↑                              ↑
                                    └── 发起报价 prime 跳转回报价 ──┘
```

开发管理是"从样品到量产"的过渡漏斗：
- **上游**：报价单（Quotation）或客户直接需求 → 创建开发案例
- **中游**：样衣三级节点（确认样 → 产前样 → 大货样）状态机跟踪
- **下游**：开发案例转大货订单（Order），同时可发起报价（prime 跳转）

### 2.2 模块边界

| 包含 | 不包含 |
|------|--------|
| 开发案例 CRUD | 报价单本身（在 Quotation 模块） |
| 6 态开发阶段状态机 | 量产订单本身（在 Order 模块） |
| 三级样衣节点状态机 | BOM 物料清单（在 BOM 模块，但详情页可展示草稿） |
| 5A 重点样衣评审门禁 | 生产管线 10 阶段（在 Order 详情页） |
| 转订单（link/autoCreate 双模式） | 客户/供应商档案（在 Relations 模块） |
| 发起报价 prime 跳转 | 产品档案（在 Products 模块） |
| EntityLink 关联图谱同步 | 审计日志本身（在 Audit 模块） |

## §3 核心概念与术语

### 3.1 DevelopmentCase（开发案例）

一个开发案例代表"为某个客户/产品做的一次开发努力"，可能经历多轮样衣修改。

| 概念 | 说明 | 代码真源 |
|------|------|---------|
| **code** | 业务编号（DEV-2026-001），唯一 | `schema.prisma` L1832 `@unique` |
| **type** | 开发类型：fabric(面料) / garment(成衣) / pp(产前) / trim(辅料) | `types.ts` L977 `DevelopmentType` |
| **stage** | 6 态：developing / shipping / feedback / revision / approved / cancelled | `types.ts` L978 `DevelopmentStage` |
| **currentRound** | 当前样衣轮次（进入 revision 时 +1） | `schema.prisma` L1850 |
| **sampleCategory** | normal(普通) / 5a(5A 重点样衣) | `schema.prisma` L1856 |
| **reviewStatus** | 5A 评审：null / pending / passed / failed | `schema.prisma` L1857 |
| **linkedOrderId** | 转订单后的订单 ID（转单后非空，幂等防重） | `schema.prisma` L1873 |

### 3.2 SampleNode（三级样衣节点）

每个 DevelopmentCase 固定 3 个样衣节点，幂等创建（`ensureSampleNodes`）。

| 级别 level | 中文名 | 业务含义 |
|-----------|--------|---------|
| `confirmation` | 确认样 | 客户确认款式/尺寸的初样 |
| `pp` | 产前样 (PP Sample) | 大货开裁前的最终确认样（产前样批准是开裁前置条件，DR-008：生产放行前置） |
| `top` | 大货样 (TOP) | 从大货首件抽取留档 |

**DR-008 高端服装多轮样品**：

| 项 | 说明 |
|---|---|
| 最少轮次 | 高端服装客户首单开发阶段至少两轮正式样品 |
| 轮次完成条件 | 每轮必须同时满足：QC 记录 + 版师归档 + 业务归档 + 客户版本号 |
| 当前限制 | 当前 SampleNode 固定 3 节点（confirmation/pp/top），不支持多轮扩展（缺口见 §14） |

**节点状态机**：`pending → making → sent → approved / revising（→ making 下一轮 round+1）`

**节点完成门禁**（DR-008）：

| 条件 | 说明 |
|------|------|
| QC 记录 | 每轮样品必须有独立 QC 检验记录 |
| 版师归档 | 版师确认样品版型/工艺已归档 |
| 业务归档 | 业务员确认客户反馈已记录 |
| 客户版本号 | 每轮样品必须记录客户侧版本号（如 V1/V2/V3） |

### 3.3 关键术语对照

| 术语 | 英文 | 代码字段 |
|------|------|---------|
| 开发单 | Development Case | `DevelopmentCase` |
| 样衣节点 | Sample Node | `SampleNode` |
| 转订单 | Convert to Order | `convertDevCaseToOrder()` |
| 5A 评审 | 5A Review | `reviewStatus` + `/review` 端点 |

## §4 核心流程

### 4.1 主流程：客户需求 → 量产转单

```
┌──────────┐    ┌──────────┐    ┌──────────┐    ┌──────────┐    ┌──────────┐
│ 客户需求  │───▶│ 创建开发 │───▶│ 样衣验证 │───▶│ 5A 评审  │───▶│ 转大货   │
│ /报价单   │    │ 案例    │    │ (3节点)  │    │ (5A only)│    │ 订单    │
└──────────┘    └──────────┘    └──────────┘    └──────────┘    └──────────┘
                       │                                              │
                       │  发起报价 prime 跳转                          │
                       └──────────────▶ 报价管理 ──────────────────────┘
```

### 4.2 开发案例 6 态状态机

```
developing ──▶ shipping ──▶ feedback ──▶ approved (终态)
    │             │             │
    │             │             └──▶ revision ──▶ shipping (下一轮)
    │             │
    └─────────────┴─────────────▶ cancelled (终态)
```

**合法转换矩阵**（`DEV_STAGE_TRANSITIONS`）：

| 当前态 | 可推进到 |
|--------|---------|
| developing | shipping, cancelled |
| shipping | feedback, cancelled |
| feedback | revision, approved, cancelled |
| revision | shipping, cancelled |
| approved | （终态） |
| cancelled | （终态） |

**5A 评审门禁**：`sampleCategory === '5a'` 的样衣，进入 `shipping` 阶段前必须 `reviewStatus === 'passed'`，否则返回 `REVIEW_REQUIRED` 错误。

**DR-008 双门禁**：

| 门禁 | 位置 | 前置条件 | 说明 |
|------|------|---------|------|
| 生产放行门禁 | 产前样（pp）approved | 产前样 QC 通过 + 客户确认 + 版师归档 + 业务归档 | 产前样是生产放行前置，未通过不得开裁 |
| 出运放行门禁 | 大货 QC | 大货出运前 QC 评审通过 | 大货出运前 QC 是出运放行前置，独立于样品 QC |

### 4.3 三级样衣节点状态机

```
pending ──start──▶ making ──send──▶ sent ──approve──▶ approved (终态)
                       │               │
                       └──revise───────┴──▶ revising ──start──▶ making (round+1)
```

**action 规则**（`ACTION_RULES`）：

| action | 前置状态 | 目标状态 | 副作用 |
|--------|---------|---------|--------|
| start | pending, revising | making | revising→making 时 round+1 |
| send | making | sent | 记录 sentDate / courier / trackingNumber |
| approve | sent | approved | 记录 approvedAt / approvedBy / feedback |
| revise | sent, making | revising | 记录 feedback / feedbackDate，清空 approvedAt |

### 4.4 转订单双模式

| 模式 | 触发条件 | 行为 |
|------|---------|------|
| `link` | 传入 `orderId` / `orderPo` | 校验订单存在 → 关联到现有订单 |
| `autoCreate` | 传入 `autoCreate: true` 或未传 orderId | 自动创建新订单（沿用客户/供应商/产品） |

两种模式均在同事务内：更新 DevelopmentCase（stage→approved, linkedOrderId, convertedAt）+ syncEntityReferences + writeAuditLog，fail closed。

## §7 状态机总览

### 7.1 DevelopmentCase 6 态状态机

见 §4.2，代码真源：`developmentCaseMutationService.ts` 的 `DEV_STAGE_TRANSITIONS` + `updateDevelopmentStage()`。

### 7.2 SampleNode 5 态状态机

见 §4.3，代码真源：`sampleNodeService.ts` 的 `ACTION_RULES` + `advanceSampleNode()`。

### 7.3 双状态机的关系

- DevelopmentCase.stage 是"粗粒度"阶段（6 态），由人工或状态推进 API 变更
- SampleNode.status 是"细粒度"节点状态（每级 5 态），由样衣节点推进 API 变更
- 两者独立但语义关联：三级样衣全 approved 通常对应 DevelopmentCase.stage = approved

## §11 业务规则关联

| # | 规则 | 接入情况 |
|---|------|---------|
| 1 | 5A 样衣评审门禁（shipping 前必须 passed） | ✅ `STAGES_REQUIRING_REVIEW` + `updateDevelopmentStage` 强校验 |
| 2 | 阶段转换合法性（DEV_STAGE_TRANSITIONS 矩阵） | ✅ 非法转换返回 `INVALID_TRANSITION` |
| 3 | revision → shipping 自动 round+1 | ✅ `updateDevelopmentStage` 中 `stage === 'revision'` 时 `currentRound+1` |
| 4 | approved 自动写 completedDate | ✅ `stage === 'approved'` 且无 completedDate 时自动填充 |
| 5 | 转订单幂等（linkedOrderId 已存在则拒绝） | ✅ 返回 `ALREADY_CONVERTED` |
| 6 | cancelled 案例不可转订单 | ✅ 返回 `CASE_CANCELLED` |
| 7 | 样衣节点 approved 为终态 | ✅ 同一级别不可退回首轮 |
| 8 | 样衣节点 revising → making 时 round+1 | ✅ `advanceSampleNode` 中处理 |
| 9 | 软删除 + EntityLink 失效同步 | ✅ `deactivateEntityLinks` 同事务 |
| 10 | 审计留痕（所有 mutation） | ✅ `writeRouteAuditLog` 同事务 |
