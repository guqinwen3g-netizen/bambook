## 四、生产就绪（投产前必须清障，本报告最高优先级发现）

### 三个"投产即炸"点

1. **部署通道分裂 × 迁移账本断链**：
   - push 链路（`deploy:server`→OPS Panel `deployUploadedPackage`）用 `prisma db push --accept-data-loss`；git 链路（`ops-deploy-main-api.sh`）用 `prisma migrate deploy`——**同一生产库被两种 schema 哲学交替作用**，账本断裂即源于此；`--accept-data-loss` 在生产无人工闸门。
   - 断链现状实测：37 个迁移中六表（FabricProfile/DevelopmentCase/Invoice/PaymentVoucher/Shipment/MaterialReturn）**CREATE 零命中**；`MaterialReturn.stockItemId` 仍在账本外（rules 以为已入 20260827143911，实测该迁移不含）；`migrate resolve` 补账流程只存在于 rules 文字，未脚本化、未演练。
   - **"Mac Mini 不从 GitHub 拉代码"铁律已被代码突破**：`ops-deploy-main-api.sh` 走 git pull、`ops-auto-deploy-panel.sh` 60 秒轮询 GitHub。
   - 根治动作：补账本（resolve 记账 + 幂等断链修复迁移）→ 生产 schema 同步收敛到 migrate deploy **单一通道** → 摘除 --accept-data-loss 默认 → `migrate diff --from-empty` 对账纳入 CI。
2. **备份真空期拿 3 年数据裸奔**：无定时备份（仅手动 backup-postgres.sh/OPS 动作）、无恢复演练、无离机副本；而 REQ2-07 数据导入完成前，存量数据唯一真本还是甲方 Excel。投产前必须：launchd 定时 pg_dump + 至少一次完整恢复演练 + 离机拷贝。
3. **弱口令 + 明文 token + 公网入口组合**：seed 硬编码 `admin@bambook.local/bambook2026`、无首登强制改密、JWT 明文 localStorage、登录入口暴露公网 jiangsupanda.com。投产前必须：强制改密/口令轮换 + token 存储升级（若 web 端对客户开放则升级为必须项）+ auth 防爆破确认。
